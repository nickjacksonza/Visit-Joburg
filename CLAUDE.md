# Visit Joburg

An independent visitor's guide to Johannesburg, built from the my-site schema, SEO and speed template. Aim: 100 in Lighthouse (performance, accessibility, best practices, SEO), clean Rich Results Test output, and pages that answer engines can read. The centrepiece is an interactive map of the city on the home page, drawn from our own SVG. `README.md` explains the layout of the repo; this file holds the working rules.

## Where things live

| Data | File | Notes |
|------|------|-------|
| Site settings, nav, city, FAQs, posts | `src/data/site.json` | |
| Tags, parts of the city, every area | `src/data/neighbourhoods.json` | Areas only |
| Every attraction | `src/data/attractions.json` | Each once; `featured` ones get a card and schema |
| Map settings | `src/data/map.json` | Hexagon sizes, Figma view frames, landmark, credit |
| Images | `src/data/images.json` | |
| Events | `content/events.json` | Owner edits at `/editor/` |
| Area lists | `content/area-lists.json` | Owner edits at `/editor/area-lists.html` |
| Map drawing and sources | `src/map/` | Generated by the map tools; see `src/map/README.md` |

A place is defined in one file and referred to everywhere else by `id`. Files in `content/` belong to the owner's editors; files in `src/data/` are edited by a developer. Every data file keeps one item per line.

## Build

    python3 build.py                        # src/ -> docs/ (standard library only)
    python3 tools/check.py                  # must pass before every commit
    python3 tools/check_schema_vocab.py     # schema.org names (needs network)
    node tools/test_editor.js               # after editor or events JSON changes
    cd docs && python3 -m http.server 3057  # preview
    pip install pillow && python3 tools/make_images.py   # placehold.co WebP/AVIF placeholders into images/

## Rules

- `docs/` is generated and committed. Rebuild and commit it with every change to `src/`, `content/`, `css/`, `js/`, `editor/` or `images/`. Never edit `docs/` by hand.
- Visible lists and their JSON-LD are built from the same data, so they stay in step. `build.py` checks every data file and fails the build on a bad entry.
- Pages are `src/pages/**.html` with front matter (`title`, `description`, `kind`, optional `robots`, `crumb`, `hero`, `body_class`). `kind` picks the schema built in `graph()` in `build.py`: `home`, `attractions`, `neighbourhoods`, `events`, `faq`, `blog`, `about`, `contact`. Pages under `blog/` are posts and need a matching entry in `posts`. Pages under `neighbourhoods/` are area guides and need a matching entry with a summary in `neighbourhoods.json`.
- Every internal link and asset path is relative to the page depth (`{{ root }}`). Never hardcode a leading `/`.
- No inline `style=""` attributes and no inline event handlers: the Content Security Policy blocks them. Inline `<script>` blocks are allowed only because `build.py` hashes them into the policy.
- `example.com` appears only in `site.json` (`domain`, `email`, placeholder URLs); static files use `__DOMAIN__`, `__EMAIL__` and `__CSP__`, which `build.py` fills in.
- Pages that must stay out of search set `robots: noindex, ...`; they are left out of the sitemap and `llms.txt`. `events.html` is noindex until real events replace the samples.
- No iframes or third-party scripts that load on page load. The CSP sets `frame-src 'none'`; widen it only for a click-to-load embed.

## Editors

- `editor/` holds two owner's editors on one password: events (`/editor/`) and area lists (`/editor/area-lists.html`). GitHub Pages can't do HTTP Basic Authentication, so the password unlocks an encrypted GitHub token (`editor/sealed.json`) and saves commit the JSON to `main`. Shared sign-in and saving live in `editor/core.js`; each editor has its rules in a `*-lib.js` file that `build.py` mirrors.

## Events editor

- `content/events.json` is the single source for events. Do not copy it into `src/data/`. `build.py` (`load_events`) validates it with the same rules as `editor/editor-lib.js`; a bad edit fails the build.
- The file keeps one event per line, soonest first. Times are local (`2026-12-05T09:00`); `timezone` adds the offset at build. Events with `published: false`, or that have ended, are left off the page and out of the schema.
- `editor/` is the owner's editor (static, served at `/editor/`, noindex, not in the sitemap or the `tools/check.py` page checks). It holds only `editor/sealed.json`, the encrypted token. Never commit a token.
- After changing `editor/editor-lib.js` or the JSON layout, run `node tools/test_editor.js`. It checks that saving does not reformat the file.
- Saves commit the JSON to `main`; `rebuild-docs.yml` rebuilds `docs/` and publishes. The workflow name must stay "Rebuild docs" because the editor follows that run.

## Area lists

- `content/area-lists.json` is the single source for area lists: popular names for clusters of suburbs (The Parks, Sandton, Town) and themes (Nightlife, Mandela's Joburg). The neighbourhoods page lists the visible ones too. The owner edits it at `/editor/area-lists.html`. One list per line: `id`, `name`, `aka`, `colour` (one of `colours` at the top of the file), `picker` and `panel` (where it shows on the map) and `areas` (area ids from `neighbourhoods.json`).
- `build.py` (`load_areas`) checks it with the same rules as `editor/area-lists-lib.js`; `node tools/test_editor.js` checks that saving doesn't reformat it. Every colour needs a `--map-hl-<colour>` token in `css/styles.css` (`tools/check.py` checks), and the editor's swatches in `editor/editor.css` match them.

## Neighbourhoods

- `src/data/neighbourhoods.json` holds the `tags` list, the 9 `regions` (parts of the city) and every area (`places`), one per line, grouped by region. It is the single source for the neighbourhoods page, the area guides, the info boxes and the map's suburbs. `build.py` (`load_places`) checks it.
- Each area has `id`, `name`, `region`, `major` (a main area: bold in the list), `tags`, `geo`, `geo_source` and `summary`. Optional: `aka` (other names), `direction` (for places outside the city), `good_for` (short text for the card), `notes` (for the team, never shown) and `map: false` for an area not drawn as itself (Soweto, drawn as its townships).
- `src/data/attractions.json` holds every attraction once: `id`, `name`, optional `aka`, `area` (the area it sits in, or null outside the city), `region`, optional `direction`, `tags`, `geo`, `geo_source` and `summary`. A `featured` attraction also has `label` (the area as shown on its card), `street`, optional `locality`, `type` (schema.org), `img` and optional `free`; it gets a card and `TouristAttraction` schema on the things-to-do page. `build.py` (`load_attractions`) checks it.
- Tags come only from the `tags` list in `neighbourhoods.json`, for areas and attractions alike. Add a new tag there before using it.
- Positions: `geo` is the place's centre, `{"lat": -26.19, "lng": 28.04}`, and `geo_source` says where it came from ("OpenStreetMap", "Wikipedia: <article>", "Google Maps", "Owner: <street corner>"). Both stay null until a place is looked up. Never guess a position. `python3 tools/fetch_map_sources.py` fills them from OpenStreetMap where it can; for the rest, ask the owner for a street corner near the middle and run `--corner "<street>" "<street>"`.
- An area with a summary gets a card on the neighbourhoods page. To give it a guide page, add `src/pages/neighbourhoods/<id>.html` with `{{ info_box }}` after the lead paragraph. Any other page can show an area's box with `{{ info_box_<id> }}` under an `h2` (the box uses an `h3`). The box lists the attractions whose `area` is that area.
- `tools/placesio.py` reads and writes both place files in their one-per-line layout; tools that change them use it.

## Map

- The base map is our own SVG, true to geography (1 km = 10 units). `tools/make_map.py` draws the draft `src/map/joburg-draft.svg` from every placed area and attraction, with outlines and roads from `src/map/source/`; it is refined in the Figma file "Visit Joburg Map" and exported back as `src/map/joburg.svg`. See `src/map/README.md`. `src/map/audit.md` lists places still without a position and every position's source.
- Every shape's `id` (its Figma layer name) is its place id in `neighbourhoods.json`. Never repeat names, tags or summaries in the SVG.
- `src/data/map.json` holds the hexagon levels, the view frames drawn on the draft for Figma, the landmark and the credit.
- Hexagons have levels (`hex_levels` in `map.json`): about 1 km at city level, about 420 m at region level (`src/map/hexes-region.svg`, loaded only when a visitor zooms into a region), about 100 m in detail views only. Never draw the 100 m level across the whole map; it is about 96,000 shapes.
- Toggles highlight areas with hexagons: the `hexes` layer has one shape per area, `hex-<place id>`. Do not shade the area outlines themselves.
- The ring road (N1 Western, N3 Eastern and N12 Southern Bypass, layer `ring-road`) is the map's main landmark. Keep it prominent and above the area shading in every view. Its turnoffs (`ring-turnoffs`, ids `turnoff-<road>-<exit>`) and bridges (`ring-bridges`) sit on top of it.
- `tools/fetch_map_sources.py` and `tools/make_map.py` are one-off tools: they need the network and `pip install shapely`. The site build never runs them.
- The map's look is a forest-green base with colour-wheel hexagons (hue from the compass direction around the city centre, richness from distance). The wheel colours stay as fill attributes in the SVG, so the no-script picture and Figma show them. Every colour the site adds (forest, dimming, the lifted columns, labels) is a `--map-*` token in `css/styles.css`, never an inline style.
- Home-page map: `build.py` (`build_map`) writes `docs/map/joburg.svg` from `src/map/joburg.svg`, or the draft until the export exists, without the view frames and `data-` notes. The page shows it as a lazy `<img>`; `js/map.js` swaps in the inline SVG when someone uses the suburb picker or taps the map, zooms to the suburb, swaps in the 420 m hexagons (`docs/map/region.json`, centres and colours from `src/map/hexes.json`, fetched on the first zoom) and lifts the suburb's hexagons as columns. While zoomed, names and symbols keep their size on screen (`--z`) and lines keep their width. The picker lists the area lists first (`group:<id>`: zoom to fit and raise all its suburbs in the list's colour), then each part of the city, starting with "All of <part>" (`all:<region id>`: stays at whole-city view and raises every suburb in that part). A second panel, Area lists, shows the lists marked `panel` as buttons. Both panels fold away under their headings. Raised columns are see-through so the roads show. At whole-city view only the area lists are named; suburb names show when zoomed in, and any suburb's name shows under the pointer.
- Keep the credit "Base outlines © OpenStreetMap contributors". Public map services (Google Maps, OpenStreetMap, Wikipedia) may be used to look up an address or a place's position; record where it came from in `geo_source`. Never trace or copy shapes, artwork or tiles from someone else's map.

## Content

- Facts about places must be checkable and slow to change. Do not list opening hours or prices for attractions; tell visitors to check with the place.
- Never invent reviews, ratings, awards or events. The site is not an official tourism body and must not suggest it is.
- Attractions use `TouristAttraction`, with a second type (`Museum`, `Park`, `LandmarksOrHistoricalBuildings`) when one fits. All places link to the `TouristDestination` node by `@id`.

## Design

- Colours come only from the tokens in `css/styles.css`: `--red --orange --yellow --green --blue --violet --offblack --offwhite --grey`, each with a dark-scheme value. `tools/check.py` checks contrast for both schemes. Yellow is a background only, with off-black text.
- Headings use Cal Sans (`--display`); body text uses the system stack.
- No auto-playing sliders or carousels. Nothing moves without the visitor asking.

## Quality bar for any page

- One `h1`, headings in order, a unique `title` (10 to 70 characters with the site name) and `description` (50 to 170), one canonical.
- Every image: `width`, `height`, `alt`, `srcset` and `sizes`. Only the hero is eager. All others are lazy.
- Schema describes only what is visible on the page. Nodes link by `@id`.
- Contrast 4.5 to 1, visible focus, 44 px targets, labelled form fields, a skip link, reduced-motion support. No script is needed to read content or use the nav.
- Third-party scripts load on first interaction or after 8 seconds. Analytics starts with consent denied.

## Deploy

- GitHub Pages: deploy from branch `main`, folder `/docs`. Merging to `main` is a live deploy. Only the owner merges.

## Voice

Plain words, concrete nouns, contractions where natural. South African English spelling (neighbourhood, colour) and `en-ZA`. No emoji. Avoid "X, not Y" constructions and em dashes. Follow ISO 24495-1 plain-language guidance.
